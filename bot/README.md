# Бот RentHUB

Второе окно в ту же базу, что и приложение. Не отдельный продукт: бизнес-правила
живут в Postgres, бот их не дублирует и обойти не может.

## Что он делает сейчас

| Умеет | Как |
|---|---|
| Привязать Telegram к аккаунту | `/start` → «Поделиться номером» → Telegram отдаёт подтверждённый номер |
| Показать активные сделки | `/deals` — что сдаёте и что арендуете, со статусами и суммами |
| Подтвердить бронь | кнопка в уведомлении и в `/deals` |
| Отменить заявку | кнопка у арендатора, пока бронь не подтверждена |
| Отметить получение вещи | кнопка у арендатора, с переспросом: отметка закрывает возможность отменить |
| Принять вещь обратно | кнопка у владельца |
| Закрыть сделку | кнопка у владельца после возврата |
| Оценить вторую сторону | пять звёзд в уведомлении о закрытии и в `/сделки`, пока оценка не поставлена |
| Заявить о порче с фото | кнопка после возврата: фото → сумма |
| Посмотреть витрину | `/каталог`, `/найти перфоратор` |
| Опубликовать вещь | `/сдать` — раздел, название, цена, депозит, где забирать, фото |
| Снять с публикации и вернуть | `/вещи` — кнопка у каждого объявления |
| Изменить цену | `/вещи` → «Изменить цену»: показывает текущую, ждёт новую |
| Показать свой профиль | `/профиль` — рейтинг, сделки, счёт объявлений, статус номера |
| Ответить на любое сообщение | ловушка в конце: «не понял» плюс кнопка «Написать организатору» |
| Передать вопрос организатору | `/поддержка` (в меню — `/support`) или та же кнопка; ответ приходит тем же ботом |
| Принять заявку на участие | у кого нет приглашения: «Поделиться номером» → заявка в очередь |
| Связаться со второй стороной | `/deals` — телефон и Telegram, после подтверждения брони |
| Подсказать команды | `/help` |
| Отвязать | `/unlink` |
| Доставлять уведомления | опрашивает `notifications` с пустым `sent_at`, шлёт, ставит отметку |
| Доставлять коды входа | через Send SMS Hook, см. README проекта |

`/deals` показывает только живые сделки — ждущие подтверждения, идущие,
возвращённые и спорные. Завершённые и отменённые остаются в приложении:
список в мессенджере отвечает на вопрос «что сейчас», а не заменяет историю.

Владельцу в строке показывается его выручка, арендатору — что он платит.
Одна и та же сделка выглядит с двух сторон по-разному, и общая сумма
запутала бы обоих.

## Запуск

```bash
cd bot
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env`, заполните три значения и запустите:

```bash
python bot.py
```

Токен бота берётся у [@BotFather](https://t.me/BotFather): `/newbot`, имя,
адрес вида `renthub_kokshetau_bot`. В ответ придёт строка вида `1234567890:AA...`.

## Почему бот держит секретный ключ

Он пишет `telegram_id` в чужие строки и отмечает доставленные уведомления —
обе операции невозможны от имени пользователя, их запрещают политики RLS.
Отсюда правило: бот запускается на машине, которую вы контролируете. Файл
`bot/.env` в `.gitignore`; репозиторий публичный.

## Как он двигает сделки, не зная правил

Переходы живут в RPC Postgres и опираются на `auth.uid()`, а у сервисного
ключа такого идентификатора нет. Раньше это и было причиной, по которой бот
только читал.

Решение — обёртки `bot_*` в миграции `20260828100000_bot_acts_as_user.sql`.
Они выставляют `request.jwt.claims` (`auth.uid()` читает именно его) и зовут
**ту же** функцию, что зовёт приложение. Поэтому бот не проверяет ни
владельца, ни статус: «подтверждать бронь может только владелец» — это ответ
`booking_confirm()`, а не проверка в Python.

Прав это боту не добавляет. Сервисный ключ и так обходит RLS целиком: прямой
`update bookings set status` был ему доступен и раньше, мимо всех проверок.
Обёртка не расширяет доступ, а сужает.

Право вызвать любую `bot_*` равно праву действовать от чужого имени —
получатель приходит аргументом. Поэтому у них явный `revoke` для `anon` и
`authenticated`, и стенд это проверяет.

Проверяет — с 03.09.2026. До этого правило было записано здесь словами, а в
пяти обёртках `revoke` стоял только для `authenticated`: `revoke all …
from public` не отбирает именной грант `anon`, который Supabase выдаёт
через `alter default privileges`. Измерено публикуемым ключом:
`bot_set_item_price` опускала цену чужого объявления с 5000 до 1,
`bot_set_item_status` снимала его с публикации. Подробности — README
проекта, раздел «Права на функции».

Стенд теперь сторожит правило, а не список: ни одна функция с параметром
`p_actor` не должна быть доступна сессионной роли. Пишете новую обёртку —
называйте параметр `p_actor`, и забытый `revoke` уронит стенд, а не уедет
в живую базу.

Ранее здесь был описан путь с пользовательским токеном. От него отказались:
`admin/generate_link` выдаёт ссылки только по email, а участники заводятся по
телефону, так что оставался бы legacy JWT-секрет — ещё один секрет рядом с
ботом, который надо хранить и однажды ротировать.

## Фото из Telegram

Снимки повреждений уезжают в тот же bucket `item-photos`, что и фото из
приложения, и тем же видом пути — `<user_id>/<файл>`. Это не косметика:
политика `item_photos_write` разрешает человеку писать только в свою папку,
а `item_photos_delete` по ней же даёт удалять. Положи бот файл в свою папку
или в корень, владелец не смог бы удалить снимок собственной вещи.

Поэтому фото, отправленное боту, видно в приложении на экране сделки — это
одно хранилище, а не две копии.

Telegram отдаёт снимки перекодированными в JPEG, поэтому бот не угадывает
тип файла, в отличие от приложения, куда фото приходит из галереи как есть.
Берётся самый крупный вариант из присланной Telegram лесенки размеров: спор
разбирают по деталям, а на превью царапину не видно.

## Чего бот не делает

**Не заменяет витрину.** `/каталог` и `/найти` отвечают на вопрос «а есть ли
вообще перфоратор», не выходя из чата, — но без фото, календаря занятости и
фильтров. Забронировать всё равно можно только выбрав даты, то есть в
приложении, и ссылка на карточку стоит у каждой строки.

**Не правит описание, фото и ориентир.** Снять с публикации, вернуть в
каталог и поменять цену из чата можно — это то, что владелец правит чаще
всего, и каждое действие помещается в одну кнопку или одно число. Остальное
требует показать все текущие значения и дать выбрать, какое менять, — это
уже экран, а не диалог.

**Не показывает избранное.** Отложенные вещи не требуют немедленного
действия, а бот нужен там, где требует. Профиль показывает: рейтинг и число
сделок — первое, что спрашивает владелец, решая, продолжать ли сдавать, а в
пассивном режиме чат единственное место, куда он вообще заходит.

**Не показывает закрытые сделки.** `/deals` — про «что сейчас».
Исключение одно: сделки, где от человека ещё ждут оценки. Таблица «чей ход»
называет это его ходом — «оцените вторую сторону, это единственное, что
осталось», — а сделать этот ход можно было ровно один раз, из уведомления о
закрытии. Пролистал — и негде. Пять последних таких сделок идут после
живых, каждая со своими звёздами.

## Что человек видит, когда сервер недоступен

Обработчики ловят отказ, который вернула база, — правило нарушено, статус не
тот, чужое объявление. Но есть второй класс сбоев: сеть. Таймаут до
Supabase, оборванное соединение, упавший DNS.

Такое исключение уходило в лог, а человек не получал ничего. Молчание в
ответ на нажатие читается как поломка приложения, причём без подсказки, что
делать. Поэтому в боте есть `@dp.error` — последний рубеж, который отвечает
«не получилось связаться с сервером, попробуйте через минуту».

Ответ пробуется дважды: сначала всплывающим окном, потом сообщением. У окна
к нажатию есть срок около пятнадцати секунд, а в обработчик ошибок мы
попадаем в том числе по таймауту в двадцать — к этому моменту окно уже не
покажется.

## Ограничение, которое не обойти

Бот не может написать первым тому, кто не начинал с ним диалог — так устроен
Telegram. Поэтому любой сценарий начинается с того, что человек открывает бота
и делится номером. Ссылку на бота стоит положить и в приложение, и в лендинг.
